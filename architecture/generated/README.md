# Generated architecture artifacts

`adr-primitive-index.json` implements the v4 contract in
[`../contracts/adr-primitive-index-v4.schema.json`](../contracts/adr-primitive-index-v4.schema.json)
and is generated by
`node tools/generate-adr-primitive-index.mjs`. It links the pinned Primitive
release to the canonical Architecture ADR set and includes the decision
inventory path and SHA-256. Every Primitive ADR reference must resolve to one
local Architecture record; both supported schemas forbid external ADR projections.
The Architecture release pins this current contract as `4.0.0`. Imported source
repository IDs, immutable source commits, original paths, per-file SHA-256
values, and declared source-preserving transformations are recorded in
`architecture/references/decision-inventory.yml`.

The generator fails when a Primitive ADR reference has no local Architecture
record. The generated index is checked for exact reproducibility in
`pnpm architecture:check`.

The catalog lock retains schema 1 for historical Primitive releases, including
their original repository locator. Schema 2 binds the current Agent
Customizations locator to native repository ID `1380894656`. Its `sourceCommit`
is the immutable commit containing the release manifest, distinct from that
manifest's prepared source commit. Index schema 4 carries the current locator
and numeric native ID in its release and primitive rows. The original index
schema 3 remains byte-for-byte unchanged and readable for historical artifacts.
Current artifacts require explicit consumer adoption of contract `4.0.0`;
changing only the repository string under the old contract is rejected.
Both lock versions remain readable; current locks cannot be downgraded by
mixing their identity fields with the historical shape.

For schema 2, generation and checking read the manifest and catalog from Git
objects and reproduce the content digest at both the selected manifest commit
and its ancestral prepared source. The reviewed dependency-free digest tool
is read from that same commit and checked against its pinned tool hash.
Unknown tool implementations and contract versions fail closed. No moving
refs, replacement objects, lazy fetching or worktree source bytes participate.
Stock Git must accept `git --no-lazy-fetch --no-replace-objects version`;
the reader probes this before inspecting objects. Unsupported hosts receive
an explicit upgrade prerequisite, preserving the offline-read guarantee.
The lock must match every projected source row and provenance field exactly.
Provide `sources/primitives` or set `AGENTIC_SOURCE_ROOT_PRIMITIVES` to the
explicit local checkout. CI retains the historical extraction checkout while
fetching its history for the separate current catalog projection. Its native
hosting identity check remains separate from local Git integrity.

The schema-2 projection is generated with `projectPrimitiveCatalog` in
`tools/primitive-catalog-source.mjs`, after `readPrimitiveCatalogSource`
verifies the immutable source. It copies catalog metadata only; it does not
import Primitive implementations or ADR prose. Draft status and provisional
decision impacts remain unchanged. Consumer compatibility, release eligibility,
runtime admission and activation require their own evidence.

`architecture-release.json` is a draft release interface. It carries an
immutable source commit, content digest, context IDs, ADR identifiers, and
integrity references. A draft does not prove live deployment, field pinning,
App installation, or GitHub enforcement.

Manifest schemaVersion 2 adds `decisionIds`, which must exactly match the
Architecture inventory, while `adrIds` must exactly match local ADR files.
`contractVersions.architectureRelease` is `5.1.0`: it retains the normalized
digest algorithm, which excludes only `sourceCommit` and `contentSha256` from
the digest input, and pins the per-family Architecture artifact contract as
`architectureArtifacts` `1.0.0`. The prepared source commit contains the
authored source, release version, status, and integrity references. The
validator recomputes the digest for both the working tree and pinned source
commit and verifies source file hashes. Consumers must dispatch by
`architectureRelease` version and adopt this release and artifact contract in
their own reviewed, gated phase before processing the manifest. Draft 78 pins
index contract `4.0.0`; earlier drafts retain their selected `3.0.0` contract.

An older consumer retains its current contract until its owner reviews and
validates an update in its own issue and pull request. This draft does not
activate a consumer migration or publish a release.

Contract 5.0.0 introduced `requirementsReference: 1.0.0`; 5.1.0 also binds
declared amendments through decision inventory 1.1.0 without changing imported
historical source identities. The selected
Requirements lock and checked QR projection bind the single normative owner.
Historical 4.0.0 artifacts keep their immutable reader/schema; consumers must
explicitly admit the new family. Prepared source pins must remain ancestors of
the checked release tree, not merely exist as unretained objects.
